# 01 · 背景知识

在看代码之前，先搞懂几个基础概念。这些概念都不难，读完这篇，后面所有内容都会容易理解很多。

## 1. 一个网页是怎么显示的？

当你在浏览器地址栏输入网址（例如 http://localhost:4321）并回车，发生了什么：

1. 浏览器向"服务器"发出一个请求（HTTP 请求）："请把首页给我"
2. 服务器找到对应的文件，把它发回浏览器（HTTP 响应）
3. 浏览器把收到的内容"渲染"成你看到的页面

一个网页本质上就是三种文件的组合：

| 语言 | 作用 | 类比 |
|------|------|------|
| HTML | 页面的**结构**（标题、段落、图片、按钮） | 房子的骨架 |
| CSS | 页面的**外观**（颜色、字体、间距、布局） | 房子的装修 |
| JavaScript (JS) | 页面的**行为**（点击展开菜单、轮播图等） | 房子的电路/开关 |

我们的项目构建后生成的 `dist/` 文件夹里，就全是这三种文件 —— 这就是"网站"本身。

## 2. 静态网站 vs 动态网站

- **静态网站**：服务器上放的就是现成的 HTML 文件，谁访问都拿到同样的文件。简单、快、便宜、几乎不会坏。**我们的网站就是静态网站。**
- **动态网站**：服务器收到请求后，临时"组装"页面（通常还要查数据库）。比如淘宝的商品页，每个人看到的都不一样。需要服务器一直运行着程序。

个人展示网站用静态网站完全够用：没有服务器成本、不怕被攻击、永远能打开。

## 3. 静态站点生成器（SSG）和 Astro

如果纯手写 HTML，4 个页面会有大量重复代码（每个页面都要复制导航栏、页脚），改一处要改四遍，维护很累。

**静态站点生成器**（Static Site Generator，简称 SSG）的思路：

- **开发时**：用"组件"写页面（导航栏写一遍，四个页面共用），内容写在 Markdown 文件里
- **构建时**：运行 `npm run build`，工具自动把组件"拼"成 4 个独立的 HTML 文件，输出到 `dist/`
- **线上时**：`dist/` 里的就是纯静态文件，跟手写的没有区别

**Astro** 就是这样的工具。它的特点：内容优先、构建产物默认零 JavaScript（页面加载飞快）、上手门槛低。

> 我们当初在 4 个方案（Astro / Vue / React / 纯手写）里选了 Astro，核心原因：**内容与代码分离，长期维护成本最低**。

## 4. Node.js 与 npm

- **Node.js**：让 JavaScript 能在电脑上（而不仅是浏览器里）运行的环境。Astro 这个工具本身是用 JS 写的，所以要装 Node.js 才能运行它。本项目要求 Node ≥ 22.12（实际用的是 v22.16.0）。
- **npm**（Node Package Manager）：Node 的包管理器，负责下载别人写好的代码库（称为"包"或"依赖"）。`npm install` 就是照着 `package.json` 里的清单把依赖下载到 `node_modules/` 文件夹。

检查本机环境是否就绪的两个命令：

```bash
node -v    # 查看 Node 版本
npm -v     # 查看 npm 版本
```

## 5. Markdown、frontmatter 与 YAML

- **Markdown**：一种简单的文本标记语法。`**加粗**`、`# 标题`、`- 列表`，用纯文本就能写出带格式的文档。你正在读的这个文件就是用 Markdown 写的。
- **frontmatter**：Markdown 文件顶部用 `---` 包起来的一段**结构化数据**。好比给这篇文章填了一张"表格头"：

```markdown
---
title: 项目名称
tags:
  - Astro
  - CSS
---
（下方才是正文）
```

- **YAML**：frontmatter 里写数据的格式。规则：`键: 值`，冒号后要有空格；列表用 `- ` 开头。

我们的网站里，所有个人信息都存在这样的 Markdown 文件里。网站构建时，Astro 读取这些文件，把数据填进页面模板 —— 这就是"内容与代码分离"的实现方式。

## 6. Git（版本管理）

Git 记录项目每次改动的"快照"。改坏了可以随时回退到任何一次历史版本，也可以和 GitHub 等平台同步。

本项目已执行 `git init` 初始化了仓库（`.git/` 文件夹），等第一版内容确认后再做首次提交。

常用命令：`git status`（看改动）、`git add .`（暂存）、`git commit -m "说明"`（提交）。

## 7. 响应式设计

同一个网站，在宽屏电脑和窄屏手机上都要好看，这叫**响应式设计**。本项目用到的核心手段：

- `<meta name="viewport">`：告诉手机浏览器"按真实屏幕宽度渲染"（写在 BaseLayout 的 head 里，是响应式的前提）
- **媒体查询（media query）**：CSS 里写 `@media (max-width: 640px) { ... }`，意思是"屏幕宽度 ≤ 640px 时，用这套样式"。我们的导航栏就是靠它实现"手机上折叠成菜单"的
- **CSS 变量**：颜色、间距等统一定义成变量，改一处全站生效（见 04 篇对 global.css 的讲解）
