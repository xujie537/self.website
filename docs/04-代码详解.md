# 04 · 代码详解

这篇逐个文件解释代码。建议把编辑器开着，边看文件边读。

## 先记住：.astro 文件的三段式结构

每个 `.astro` 文件由三部分组成：

```astro
---
// 第一段：脚本区（frontmatter）
// 写 JavaScript/TypeScript：读取数据、定义变量、接收参数
const name = '小明';
---

<!-- 第二段：模板区（HTML）
     用 { } 把脚本区的变量嵌进 HTML -->
<p>你好，{name}</p>

<style>
  /* 第三段：样式区（CSS） */
  p { color: brown; }
</style>
```

- **脚本区**算数据，**模板区**摆结构，**样式区**管外观
- `{表达式}` 是模板区嵌入数据的语法，类似"留空待填"
- `<style>` 是**组件级作用域**的：Astro 构建时会自动给本组件的元素加唯一标记，样式不会"污染"其他组件。而 `src/styles/global.css` 是全局样式（在 BaseLayout 里引入），作用于全站

## 1. package.json —— 项目的"身份证"

```json
{
  "name": "self-website",        // 项目名（小写、无空格）
  "type": "module",              // 使用最新的 ES 模块语法
  "version": "0.1.0",            // 版本号
  "private": true,               // 私有项目，防止误发布到 npm 公共仓库
  "scripts": {                   // 自定义命令：npm run 后面跟的名字
    "dev": "astro dev",          //   → 启动开发预览
    "build": "astro build",      //   → 构建静态文件
    "preview": "astro preview"   //   → 预览构建产物
  },
  "dependencies": {              // 依赖清单：项目用到的外部库
    "astro": "^7.3.3"            //   ^ 表示"7.x.x 的最新版都可以"
  }
}
```

要点：

- `npm run dev` 其实就是执行 scripts 里 dev 对应的命令 `astro dev`
- 以后想加依赖：`npm install 包名`，它会自动写进 dependencies
- `^7.3.3` 里的 `^` 是语义化版本规则：主版本 7 不变，允许之后 7.x 的更新

## 2. astro.config.mjs —— Astro 的配置

```js
import { defineConfig } from 'astro/config';

export default defineConfig({
  site: 'https://example.com',  // 网站正式域名，部署后需改
});
```

目前只有一项配置：`site`。它的用途是让生成的 SEO 标签能写出完整的绝对网址。**部署上线时必须改成真实域名。** Astro 的哲学是"默认值够用就不配"，所以我们的配置文件很短 —— 这是框架设计得好，不是偷懒。

## 3. tsconfig.json 与 env.d.ts —— TypeScript 配置

```json
{
  "extends": "astro/tsconfigs/strict",  // 继承 Astro 官方推荐的严格配置
  "include": [".astro/types.d.ts", "**/*"],
  "exclude": ["dist"]
}
```

- TypeScript 是"带类型检查的 JavaScript"，能在写代码阶段就发现错误
- `extends` 直接借用 Astro 官方的严格模式配置，自己不用写一大堆
- `env.d.ts` 里的 `/// <reference path="../.astro/types.d.ts" />` 引入了 Astro 自动生成的类型。这样编辑器和构建工具才知道 `getCollection('projects')` 返回的数据长什么样，写错字段会有红色波浪线提示

## 4. .gitignore —— 哪些文件不进版本管理

```
node_modules/   # 依赖（几百 MB，npm install 就能重新生成，不该入库）
dist/           # 构建产物（npm run build 就能重新生成，不该入库）
.astro/         # Astro 内部缓存
.env            # 环境变量（可能含密钥）
```

> 方法论：**能被重新生成的东西不入库**，只入库"源头"。

## 5. content.config.ts —— 内容数据的"结构规范" ★

这是本项目最有"工程感"的文件，配合 `src/content/` 使用。以项目集合为例：

```ts
import { defineCollection } from 'astro:content';
import { z } from 'astro/zod';                    // 校验库
import { glob } from 'astro/loaders';

const projects = defineCollection({
  loader: glob({ base: './src/content/projects', pattern: '**/*.md' }),
  schema: z.object({
    title: z.string(),              // 必填字符串
    description: z.string(),        // 必填字符串
    tags: z.array(z.string()).default([]),  // 字符串列表，默认空
    link: z.string().optional(),    // 可选字符串
    github: z.string().optional(),
    order: z.number().default(0),   // 数字，默认 0
  }),
});

export const collections = { site, about, experience, projects };
```

逐部分解释：

- **loader（装载器）**：告诉 Astro"去哪里找内容"。`glob` 是"按文件路径模式匹配"：base 指定文件夹，pattern `**/*.md` 表示该文件夹下所有 `.md` 文件，每个文件成为一个"条目"。
- **schema（模式/规范）**：用 `z`（一个叫 Zod 的校验库）声明每个条目 frontmatter 里允许有哪些字段、什么类型、是否必填。`.optional()` 表示可以不填；`.default(值)` 表示不填时用默认值。
- **作用**：构建时 Astro 会逐个校验内容文件。字段写错（比如 order 写了文字）会**立即报错并指出哪个文件哪一行** —— 相当于给"内容"也加了类型检查，这是长期维护的安全网。
- 一个细节：可选字段我们约定"留空写 `""`"（空字符串）而不是删掉这行。因为页面上用 `字段 && ...` 判断时，空字符串自动隐藏对应 UI，比"字段不存在"更好处理。

四个集合：`site`（站点信息）、`about`（关于我）、`experience`（经历）、`projects`（项目）。

## 6. global.css —— 设计令牌（CSS 变量）★

```css
:root {
  --color-bg: #faf6f0;          /* 页面米白底 */
  --color-accent: #c4703f;      /* 强调暖橙 */
  --radius-md: 14px;            /* 圆角 */
  --shadow-soft: 0 4px 20px rgba(120, 90, 60, 0.08);  /* 柔和阴影 */
  ...
}
```

- `:root` 里定义的 `--xxx` 是 **CSS 自定义属性（俗称"变量"）**
- 全站任何地方用 `var(--color-bg)` 引用它
- 好处：想换主题色，只改这一个地方，全站生效 —— 这叫**设计令牌（design token）**思想
- 配色依据："暖色柔和风" = 米白底 + 暖棕文字 + 陶土橙强调，低对比但不失可读性

文件后半部分是"工具类"（utility class），比如：

```css
.container { max-width: 920px; margin: 0 auto; padding: 0 24px; }
```

`.container` 是"内容列"的标准写法：屏幕再宽，正文也不会被拉得太宽（一行太长难阅读），并且始终居中。`.card`（白底圆角卡片）、`.tag`（小圆角标签）、`.btn`（胶囊按钮）同理，都是全站复用的外观积木。

## 7. BaseLayout.astro —— 页面总框架 ★

```astro
---
const { title, description } = Astro.props;   // 接收"参数"
const info = await getEntry('site', 'info');  // 读取站点信息条目
const siteInfo = info.data;                   // .data 是 frontmatter 数据
const currentPath = Astro.url.pathname;       // 当前网址路径
---

<html lang="zh-CN">
  <head>…meta 标签…</head>
  <body>
    <Header siteInfo={siteInfo} currentPath={currentPath} />
    <main>
      <slot />          <!-- ← 关键：子页面内容插到这里 -->
    </main>
    <Footer siteInfo={siteInfo} />
  </body>
</html>
```

三个重要概念：

1. **props（参数传递）**：每个页面用 `<BaseLayout title="经历" description="…">` 调用布局时，标签属性就是 props，在脚本区通过 `Astro.props` 拿到 —— 和函数传参是一个道理。
2. **slot（插槽）**：`<slot />` 是"占位符"。调用方写 `<BaseLayout>这里的内容</BaseLayout>` 时，中间的内容会被放到 slot 的位置。布局管"骨架"，页面管"血肉"。
3. **组件复用**：Header 和 Footer 是独立组件，布局只管把它们摆进来。一处定义，四页共用。

head 里的标签值得认识：

```html
<meta name="viewport" content="width=device-width, initial-scale=1" />
<!-- 让手机按真实屏幕宽度渲染（响应式的前提） -->
<meta name="description" content={description} />
<!-- 搜索引擎结果页显示的描述文字 -->
<meta property="og:title" content={fullTitle} />
<!-- og = Open Graph：分享到微信/社交平台时显示的卡片标题 -->
```

## 8. Header.astro —— 导航 + 手机菜单 ★

**渲染导航列表**（脚本区定义数据，模板区循环渲染）：

```astro
const navItems = [
  { href: '/', label: '关于', match: '/' },
  { href: '/experience/', label: '经历', match: '/experience/' },
  ...
];

{
  navItems.map((item) => (
    <a href={item.href}
       class:list={['nav-link', { active: currentPath === item.match }]}>
      {item.label}
    </a>
  ))
}
```

- `map`：对数组里每个元素渲染一次 —— "数据驱动视图"的雏形。以后加页面，只往 navItems 里加一行，导航自动多一项
- `class:list={[...]}`：Astro 的动态 class 写法。数组里的对象 `{ active: 条件 }` 表示"条件为真才加 active 这个 class"
- `currentPath === item.match`：当前网址与导航项匹配时高亮。currentPath 是布局传进来的

**手机端菜单**（响应式的核心，CSS + 少量 JS 配合）：

```css
@media (max-width: 640px) {
  .site-nav { display: none; ... }   /* 默认隐藏导航 */
  .site-nav.open { display: flex; }  /* 有 .open 时展开 */
  .nav-toggle { display: block; }    /* 显示"菜单"按钮 */
}
```

```html
<script>
  // 点击"菜单"按钮 → 给导航加/去掉 .open 这个 class
  const toggle = document.getElementById('nav-toggle');
  const nav = document.getElementById('site-nav');
  toggle?.addEventListener('click', () => {
    const open = nav?.classList.toggle('open') ?? false;
    toggle.setAttribute('aria-expanded', String(open));
    toggle.textContent = open ? '关闭' : '菜单';
  });
</script>
```

原理：CSS 控制"什么状态长什么样"，JS 只负责切换状态（加/删 class）。这是标准的交互模式，也是全站**唯一**一段 JavaScript。

几个小点：

- `?.` 是"可选链"：元素不存在就不执行，避免报错
- `aria-expanded` 是无障碍属性：告诉屏幕阅读器菜单是否展开
- 桌面端菜单按钮是 `display: none` 的，只在手机宽度出现
- 头部的半透明毛玻璃背景用了两个现代 CSS：`color-mix()`（混合颜色，做出 92% 透明的背景色）+ `backdrop-filter: blur(8px)`（背景模糊）

## 9. index.astro —— 关于我（首页）

**读取并渲染 Markdown 正文**：

```astro
const aboutEntry = await getEntry('about', 'about');  // 取"关于我"条目
const { Content } = await render(aboutEntry);         // 把 Markdown 编译成组件
const { skills, education } = aboutEntry.data;        // 取 frontmatter 字段

<div class="prose"><Content /></div>                  <!-- 正文渲染在这里 -->
{skills.map((skill) => <span class="tag">{skill}</span>)}  <!-- 技能标签 -->
```

- `render()` 是 Astro 7 的 API：把 Markdown 编译成可渲染的 HTML 组件
- 正文和字段分开用：正文走 `<Content />`，结构化字段（技能、教育）自己排版 —— 这就是 frontmatter 的意义

**条件渲染**（头像）：

```astro
{
  siteInfo.avatar ? (
    <img class="hero-avatar" src={siteInfo.avatar} alt={siteInfo.name} />
  ) : (
    <div class="hero-avatar hero-avatar-text">{siteInfo.name.slice(0, 1)}</div>
  )
}
```

- `条件 ? A : B` 是三元运算符：填了头像路径就显示图片，没填就显示"姓名首字"圆形标
- `slice(0, 1)` 取字符串第一个字符

**响应式字号**：

```css
.hero-name { font-size: clamp(2rem, 5vw, 2.6rem); }
```

`clamp(最小值, 首选值, 最大值)`：字号随屏幕宽度在 2rem~2.6rem 之间平滑变化，手机小屏不会溢出。

## 10. experience.astro —— 经历时间线

```astro
const experiences = (await getCollection('experience')).sort(
  (a, b) => b.data.order - a.data.order,
);
```

- `getCollection('experience')`：取出该集合的**所有**条目（对比 getEntry 取单个）
- `.sort(...)`：按 order 字段从大到小排序。`b - a` 为正数时 b 排 a 前面

**时间线的视觉实现**（纯 CSS，无 JS）：

```css
.timeline {
  border-left: 2px solid var(--color-border);  /* 左侧竖线 */
  padding-left: 20px;
}
.timeline-item::before {
  content: "";                  /* 每个卡片前的圆点 */
  position: absolute; left: -27px;
  width: 12px; height: 12px; border-radius: 50%;
  background: var(--color-accent);
  box-shadow: 0 0 0 4px var(--color-accent-soft);  /* 圆点外圈光环 */
}
```

`::before` 是**伪元素**：不用写 HTML，纯 CSS 生成一个装饰性元素。`box-shadow` 把模糊值设成 0 时（0 0 0 4px）可以画出"描边"效果 —— 这里用它做圆点外的浅色光环。

## 11. projects.astro + ProjectCard.astro —— 组件拆分

projects.astro 只负责：取数据、排序、套网格：

```astro
{projects.map((project) => <ProjectCard project={project} />)}
```

每个项目的展示细节封装在 ProjectCard.astro 里（接收 `project` 这个 prop，渲染卡片）。这叫**组件化**：页面管"有哪些"，卡片管"长什么样"。以后想改卡片样式，只动 ProjectCard 一个文件。

**响应式网格**（关键一行）：

```css
.project-grid {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(260px, 1fr));
}
```

翻译：列宽最小 260px，剩余空间平均分配，列数自动适应屏幕宽度 —— 电脑宽屏 3 列、平板 2 列、手机 1 列，**一行 CSS 搞定三种设备的布局**，这就是现代 CSS 网格布局（Grid）的威力。

## 12. contact.astro —— 联系页

主要模式是"有条件才显示"：

```astro
{
  s.github && (
    <div class="card contact-item">
      <h2>GitHub</h2>
      <a href={s.github}>{s.github.replace('https://', '')}</a>
    </div>
  )
}
```

- `s.github && (...)`：github 字段非空（truthy）才渲染整个卡片；空字符串 `""` 是 falsy，自动隐藏 —— 所以 info.md 里没填的社交账号不会出现
- `replace('https://', '')`：显示时去掉协议前缀，更简洁
- 特殊链接协议：`mailto:邮箱`（唤起邮件客户端）、`tel:电话`（手机唤起拨号）

## 13. 404.astro —— 兜底页面

访问不存在的路径时显示。它是 Astro 的约定文件名（`src/pages/404.astro`），构建时输出为 `404.html`。托管平台会自动用它做"找不到页面"的兜底。

## 14. 内容文件长什么样

以经历为例（`src/content/experience/job-1.md`）：

```markdown
---
company: 示例公司 A
role: 前端工程师（示例）
period: 2023.07 - 至今
current: true
location: 上海
order: 1
highlights:
  - 负责 XX 产品核心模块开发
  - 与设计、后端协作，推动 XX 项目按期上线
---

（正文可不填）
```

- `---` 之间是 frontmatter（YAML 格式），字段必须符合 content.config.ts 的 schema
- `highlights` 是多行列表：`- ` 开头
- `period` 是纯文本、原样显示 —— 故意不用日期类型，就是为了"写了什么显示什么"
- 排序约定：`order` 越大越靠前（新条目给更大的号）

## 学习建议

读代码时按这个顺序：先 BaseLayout（骨架）→ Header（复用组件 + 交互）→ index（取内容渲染）→ experience（列表 + 排序）→ projects（组件拆分 + 网格）→ content.config.ts（回头看数据从哪来）。
