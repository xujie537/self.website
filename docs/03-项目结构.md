# 03 · 项目结构

看一眼整个项目的"地图" —— 每个文件是干什么的：

```
self.website/
├── CLAUDE.md                 产品文档 + 协作规则 + 技术决策记录
├── README.md                 项目说明（含内容维护指南）
├── docs/                     本技术文档包
├── package.json              项目定义：依赖清单、常用命令
├── package-lock.json         依赖的精确版本锁定（npm 自动生成，勿手改）
├── astro.config.mjs          Astro 配置
├── tsconfig.json             TypeScript 配置
├── .gitignore                告诉 git 忽略哪些文件
├── node_modules/             安装的依赖（npm install 生成，勿手改，不入库）
├── public/                   静态资源，构建时原样复制到网站根目录
│   └── favicon.svg           浏览器标签页上的小图标
├── src/                      源码 —— 我们写的代码都在这里
│   ├── env.d.ts              TypeScript 类型声明文件
│   ├── content.config.ts     内容集合定义（内容数据的"结构规范"）
│   ├── content/              ★ 所有个人信息（Markdown）★
│   │   ├── site/info.md      姓名、一句话介绍、联系方式
│   │   ├── about.md          「关于我」正文、技能、教育背景
│   │   ├── experience/       经历条目（一个文件一条）
│   │   └── projects/         项目条目（一个文件一个）
│   ├── layouts/
│   │   └── BaseLayout.astro  页面总框架（<html>、导航、页脚、SEO）
│   ├── components/
│   │   ├── Header.astro      顶部导航（含手机端菜单）
│   │   ├── Footer.astro      页脚
│   │   └── ProjectCard.astro 项目卡片
│   ├── pages/                页面（文件名 = 网址路径）
│   │   ├── index.astro       → /           （关于我）
│   │   ├── experience.astro  → /experience/（经历）
│   │   ├── projects.astro    → /projects/  （项目）
│   │   ├── contact.astro     → /contact/   （联系）
│   │   └── 404.astro         → 页面不存在时显示
│   └── styles/
│       └── global.css        设计令牌（CSS 变量）+ 全局样式
└── dist/                     构建产物（npm run build 生成，勿手改）
```

## 关键设计思想：内容与代码分离

日常维护的三个"圈"，从常用到不常用：

- 改**内容**（加经历、改联系方式）→ 只动 `src/content/`，一行代码都不用看
- 改**外观**（配色、圆角）→ 只动 `src/styles/global.css` 顶部的变量区
- 改**结构**（加页面、改导航）→ 才需要碰 `src/pages/`、`src/components/`

维护一个个人网站的大部分日常操作，都落在第一个圈里。

## 数据是怎么流动的？

```
src/content/*.md（内容）
      ↓  build 时被读取
src/content.config.ts（校验数据格式，不合格当场报错）
      ↓  通过校验的数据交给页面
src/pages/*.astro（页面模板：取数据、排序、排版）
      ↓  套上总框架
src/layouts/BaseLayout.astro（<html> 骨架 + 导航 + 页脚）
      ↓  生成
dist/*.html（最终网站文件，双击可打开）
```
