# 02 · 开发流程与方法

这篇回顾本项目实际经历的完整流程：每一步做了什么、用了什么命令、为什么这么做。这套流程可以复用到任何新项目。

## 总流程

```
需求 → 产品文档 → 技术选型 → 搭建骨架 → 开发页面 → 本地验证 →（部署，待做）
```

## 第 1 步：明确需求，写成产品文档

先不写代码，把"要做什么"写清楚：

- 目标：个人展示网站，用于简历/求职/作品长期维护
- 功能：About / Experience / Projects / Contact 四个页面
- 约束：Windows 电脑 + 手机都能用（响应式设计）

产物：`CLAUDE.md`（产品文档 + 协作规则 + 技术决策记录）。这份文件还有一个作用：Claude 每次工作都会先读它，保证后续所有工作都围绕同一份需求。

> 方法论：**先定义清楚"做成什么样"，再动手**。需求不清晰时写代码，返工率极高。

## 第 2 步：技术选型 —— 列方案、比优劣、做决策

面对"用什么技术"这种问题，标准做法不是拍脑袋，而是：

1. 列出 2-4 个候选方案
2. 用统一维度比较（学习成本、维护成本、生态、性能等）
3. 给出推荐和理由
4. 由做决定的人拍板

本项目做过的选型（记录在 CLAUDE.md 的"技术决策记录"表里）：

| 决策点 | 选定方案 | 关键理由 |
|--------|----------|----------|
| 技术栈 | Astro | 内容与代码分离，长期维护成本最低 |
| 样式方案 | 手写 CSS | 小站够用、代码透明、无额外学习成本 |
| 页面结构 | 多页面 | 独立网址，利于分享与搜索引擎收录 |
| 网站语言 | 中文 | 面向国内求职场景 |
| 部署平台 | 暂不部署 | 先本地开发，后续再定 |
| 包管理器 | npm | Node 自带，最通用 |

> 方法论：每个方案都有适用场景，**没有绝对的好坏**，只有"在当前目标下哪个更合适"。关键是把"为什么"说清楚，把决策记录下来。

## 第 3 步：环境检查

```bash
node -v   # v22.16.0 —— 满足 Astro 7 要求的 ≥ 22.12
npm -v    # 10.9.2
```

装软件之前先确认环境，避免"装到一半发现环境不兼容"。

## 第 4 步：搭建项目骨架

创建基础文件：

- `package.json` —— 项目"身份证"：名字、依赖清单、常用命令（scripts）
- `astro.config.mjs` —— Astro 的配置文件
- `tsconfig.json` —— TypeScript 的配置
- `.gitignore` —— 告诉 git 哪些文件不纳入版本管理
- `src/pages/index.astro` —— 第一个页面（占位）
- `src/styles/global.css`、`public/favicon.svg`

然后执行：

```bash
npm install    # 按 package.json 下载依赖
git init       # 初始化版本管理
npm run build  # 试构建 —— 确认骨架能跑通
```

> 方法论：**小步验证**。每搭一步就跑一次，出错时问题范围很小；而不是全部写完再一次性面对一堆报错。

## 第 5 步：开发页面（迭代循环）

后面的工作是一个循环：

```
写代码 → npm run build 验证 → 看效果（npm run dev）→ 调整
```

开发过程中用 `npm run dev` 启动预览服务器（http://localhost:4321），改动保存后浏览器自动刷新 —— 这叫**热更新**。

## 第 6 步：本地验证

- 电脑浏览器：http://localhost:4321
- 手机（与电脑同一 Wi-Fi）：用 `npm run dev -- --host` 启动，访问它输出的局域网地址（如 http://192.168.0.171:4321）
- 构建产物验证：`npm run build` 后，`dist/` 里的 HTML 文件双击即可打开

## 命令速查表

| 命令 | 作用 |
|------|------|
| `npm install` | 安装依赖（新环境首次必做） |
| `npm run dev` | 启动开发预览（带热更新） |
| `npm run dev -- --host` | 启动预览并允许手机等局域网设备访问 |
| `npm run build` | 构建静态文件到 `dist/` |
| `npm run preview` | 在本地预览构建产物 |
| `astro dev stop` | 停止后台的开发服务器 |
| `node -v` / `npm -v` | 查看环境版本 |
| `git status` | 查看改动 |
| `git add .` + `git commit -m "…"` | 提交一次改动 |
